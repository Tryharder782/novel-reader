# Спецификация Intelligent UI (`UI_SPEC.md`)

Этот документ описывает разметку глав и глоссария для PWA-читалки.
При переводе новых глав нужно строго следовать этой спецификации.

---

## 1. Структура файлов контента

```
reader/content/<slug>/
├── novel.json          # Описание тайтла и главного героя
├── glossary.json       # Глоссарий (персонажи, места, предметы, термины) с защитой от спойлеров
└── chapters/
    ├── 0007.md
    ├── 0008.md
    └── ...
```

### Формат Frontmatter каждой главы (`chapters/XXXX.md`)

```yaml
---
number: 7
title: "Экзамен по распределению (2)"
hero_level: 26
source: "https://fictionwithfriction.com/novelbin/511334/66828.html"
date: 2026-10-29
---
```
- `number` *(обязательно, число)* — номер главы.
- `title` *(обязательно, строка)* — название главы (без префикса «Глава N»).
- `hero_level` *(опционально, число)* — текущий уровень главного героя в этой главе. Если указан, карточки `status` автоматически показывают полосу сравнения уровней с главным героем.

---

## 2. Главный принцип оформления

- **Обычный текст, диалоги и мысли героя** остаются чистым Markdown (абзацы, тире `—`, мысли курсивом `*«…»*`).
- **Компоненты Intelligent UI** применяются **только** там, где в самом мире новеллы появляется системное окно, статус персонажа, карточка предмета/навыка, применение заклинания, таймер или смена лица повествования (POV).

---

## 3. Компоненты Intelligent UI

Все компоненты поддерживают два визуальных режима в читалке (переключаются в настройках на лету):
1. **Сдержанный (`minimal`)** — спокойные тёмные карточки в стиле ChatGPT.
2. **Игровой (`game`)** — светящиеся системные окна с уголками-скобками и моноширинными метками.

### 3.1. Окно статуса персонажа / монстра (`status`)

````markdown
```status
name: Перникус Созерцатель
level: 105
race: Демон
elements: [Тьма, Лёд]
danger: Высокая
```
````

Поля:
- `name` — имя персонажа или монстра.
- `title` *(опц.)* — титул или прозвище под именем.
- `level` — уровень (число или `???`).
- `race` — раса (`Человек`, `Демон`, `Магический зверь` и т.д.).
- `elements` — список стихий через запятую или в `[...]`. Автоматически раскрашиваются по стихиям (`Лёд`, `Ветер`, `Вода`, `Огонь`, `Тьма`, `Свет`, `Молния`, `Земля`, `Растения`).
- `danger` — уровень угрозы (`✕` / `Нет`, `Низкая`, `Средняя`, `Высокая`, `Крайняя`).
- `compare: нет` *(опц.)* — отключить полосу сравнения с главным героем.
- Текст после пустой строки *(опц.)* — дополнительное описание.

---

### 3.2. Карточка предмета (`item`)

````markdown
```item
name: Заготовленный туман
tier: 7

При разбивании флакона мгновенно создает плотную завесу тумана стихии воды. Эффект длится 20 секунд.
```
````

Поля:
- `name` — название предмета.
- `tier` — тир редкости (от `9` — обычный до `1` — легендарный). Читалка сама построит 9-сегментную шкалу редкости и раскрасит бейдж.
- Текст после пустой строки — описание эффекта предмета.

---

### 3.3. Навык (`skill`)

````markdown
```skill
name: Создание льда
type: Активный
level: ★1

Позволяет создавать глыбы и формы из обычного льда.
```
````

---

### 3.4. Характеристики и их рост (`stats`)

````markdown
```stats
title: Статус Исаака
rows:
  - Уровень: 26 → 28 (UP)
  - Запас маны: Ранг E
  - Стихийный резонанс: Высокий (MAX)
```
````
- Стрелки `→` или `->` красиво подсвечиваются.
- Пометки `(UP)`, `(MAX)`, `(NEW)` в конце строки превращаются в цветные бейджи.

---

### 3.5. Системное уведомление (`system`)

````markdown
```system
kind: warning
label: Внимание
title: Негативный эффект рассеивается!

Дополнительный текст уведомления (если есть).
```
````
Значения `kind`: `info` (по умолчанию), `warning`, `danger`, `success`, `quest`, `levelup`.

---

### 3.6. Задание / Испытание (`quest`)

````markdown
```quest
label: Экзамен
title: Распределительный тест в лесу Дельфин

Соберите как можно больше крупиц маны и выживите до окончания таймера.
conditions:
  - Находиться в пределах барьера леса Дельфин
rewards:
  - Распределение в классы A–D по рейтингу
fail:
  - Потеря сознания или выход из боя
```
````

---

### 3.7. Таймер / Отсчёт времени (`timer`)

````markdown
```timer
title: До появления демона
value: 00:10:00
caption: На часах 18:50
```
````

### 3.8. Примечание переводчика (`note`)

````markdown
```note
label: Примечание

В оригинале использован корейский мем из StarCraft про глухую оборону зергов (버티기).
```
````

---

### 3.9. Заклинания (`spell`)

Распознаются **автоматически** без специальной разметки!
Достаточно написать строку в каноничных японских кавычках:

```markdown
「Холодное рассеивание (Стихия Льда, ★1)」
```
- Если такая конструкция стоит **отдельным абзацем** — она превратится в центрированную плашку заклинания с иконкой и цветом стихии.
- Если стоит **внутри абзаца** — превратится в аккуратный инлайн-чип.

---

### 3.10. Однострочные директивы

- `::break` (или стандартный `---` / `***`) — красивый разделитель сцен.
- `::pov Кайя Астреан` — разделитель со сменой точки зрения (POV).
- `::sfx КУ-У-У-У-У-У-У-У─────!!!` — центрированный звуковой эффект для крупных взрывов и рёва.

---

## 4. Глоссарий без спойлеров (`glossary.json`)

В тексте главы термины из глоссария подсвечиваются **спокойным серым хайлайтом** (не синей ссылкой и без подчёркивания, чтобы не отвлекать от чтения). По умолчанию в каждой главе подсвечивается только **первое упоминание** каждого термина (в настройках можно переключить на «Все» или «Выкл.»).

Формат элемента в `glossary.json`:

```json
{
  "id": "kaya-astrean",
  "name": "Кайя Астреан",
  "original": "Kaya Astrean",
  "category": "Персонажи",
  "match": ["Кайя", "Кайи", "Кайе", "Кайю", "Кайей", "Кайя Астреан"],
  "entries": [
    {
      "from": 7,
      "text": "Второе место среди первокурсников факультета магии (ур. 90). Стихии Ветра и Льда. Ошибочно считает Исаака скрытым Архимагом."
    },
    {
      "from": 8,
      "text": "Защитила Исаака от удара Тристана Хамфри в спину, в одиночку подавив его заклинание 4-го ранга."
    }
  ]
}
```
- В `match` можно использовать `*` для любых буквенных окончаний (например, `"Тристан*"` сработает на *Тристан, Тристана, Тристану, Тристаном*).
- При клике на термин в главе `N` читалка показывает **только те записи `entries`, у которых `from <= N`**. Читатель никогда не увидит спойлеров из будущих глав.
